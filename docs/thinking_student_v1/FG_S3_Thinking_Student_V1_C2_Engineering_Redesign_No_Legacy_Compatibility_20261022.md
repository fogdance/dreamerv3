# FG-S3 Thinking Student V1 — C2工程架构重设计（无旧功能兼容、训练资产持续复用）

> 日期：2026-10-22  
> 状态：**C2修订版设计建议，已做反向Review；非已实现代码、非Codex任务书**。  
> 优先级：替代前一版C2中“保留旧F1–F4可运行、为旧流程维持适配、用代码/模型Hash做准入”的内容。  
> 不变：A1–A6冻结的学生大脑能力和数学语义、B1老师基本职责、B2课程目标，以及Native金融规则。

## 1. 四条工程原则

1. **两个仓库均不做旧功能兼容**：Gym和DreamerV3都只是基础代码；新架构可以直接替换、修改或删除旧S3入口、旧Stage/Gate、旧API、旧配置和旧课程，不为无用功能维护后向兼容。
2. **底座只按实际价值复用**：原生金融结算、可靠因果行情、基础张量网络和训练工具能用则复用；不能用或复用成本过高则改写、删除或新建。Dreamer原功能不是必须保留的产品功能。
3. **Checkpoint默认可以继续利用**：日常代码变更不因commit/code hash而拒绝加载；中断后默认继续训练。遇到真实参数结构变化，由开发人员调整加载或做选择性权重继承，新增参数正常初始化，不建设自动兼容性认证和严格门禁。
4. **教材默认继续利用**：已有行情、账户轨迹、后果事实和合法训练样本不因生成程序代码Hash变化整体报废；开发人员负责格式与标签语义适配，不建设Corpus版本认证或Hash准入系统。

### 不兼容旧软件接口 ≠ 丢弃训练资产

- **明确不保证**旧S3程序、配置、旧Gate、旧CLI、旧训练Stage和旧考试入口还可以运行。
- **默认保留与复用**已有模型权重、市场基础训练结果、可解释的Native轨迹和教材。
- “默认可用”是一项**人工开发责任与工作目标**，不是声称不同结构的张量自动兼容。参数形状真的改变时，尽量复用可加载部分；语义改变的旧标签必须由开发人员转换、重新派生或局部舍弃，绝不冒充新标签。
- 不增加基于代码Hash、Git SHA、生成器Hash的拒绝运行逻辑、迁移证书、模型/教材准入Gate、兼容性注册中心。普通加载器仍需要保证不会把错误参数或错误标签当作正确数据——这是功能正确性，而非“兼容性验证体系”。

## 2. 两个仓库的新职责（允许随开发微调）

| 代码底座 | 建议主要负责 | 不再承担的额外义务 |
|---|---|---|
| Gym | Native金融Env、价格和账户推进、因果市场Observation、自然教材/交易经历、历史事实与双分支反事实计算 | 维持旧S3 API/旧训练Stage/旧教师与旧质量门禁的兼容性 |
| DreamerV3 | 完整学生大脑、外生市场表征、A6分目标Learner、唯一Policy入口、自主采集调度、模型训练/继续训练/独立推理 | 保留原Dreamer所有功能、原版Actor/RSSM Action语义、原F3/F4训练路线 |

- 这是**低耦合建议**，不是强制跨仓库抽象层。Gym的教学回放需要学生后续策略时，优先接收一个冻结Policy调用接口或回调，避免Gym直接导入整个Dreamer运行器。
- 使用同一权威主线的开发工作区即可。不单独维护旧程序镜像或双路径适配版。
- 遇到无用的旧Stage/Gate/审计代码，可以在妨碍新主线时直接移除；不必开发早期大规模清理运动。

## 3. 按新合同重新划分复用 / 修改 / 新建

| 部分 | C2方案 | 说明 |
|---|---|---|
| Native单仓位、3手做空、TP5/SL30、Reward | **优先复用，有必要可直接改** | 保留金融交易语义，不保留旧接口 |
| 1m/15m/partial MACD因果观察 | **优先复用/精简** | 以A2单一决策时钟为准 |
| 历史价格、天然轨迹、P0–P4教材 | **默认保留资产，读取接口可重做** | 可用事实和标签继续复用；语义冲突人工修正 |
| 多尺度市场Encoder、已有F1权重 | **选择性继承** | 网络权重是可利用资产，不要求保留旧F1执行流程 |
| 原Dreamer RSSM | **只借鉴/复用合适部分** | 外生Market Brain不把ADD/WAIT作为致因输入 |
| Account Encoder、Shared State | **按A2直接实现** | 不为旧观测字段固定接口 |
| Outcome Brain | **利用已有事实样本，按A3重新组织** | 竞争TP/SL事件、条件风险、右删失；不强制四旧Head共存 |
| Value Brain | **按A4新建核心能力** | 当前学生策略条件的Q_ADD/Q_WAIT，不以旧Quality Q名字代替 |
| Reasoning与Value-Anchored Integrator | **按A5新建** | 一个Final Actor，一个动作出口 |
| 策略调用/Collector/考试 | **可复用底层调度，直接替换旧Policy** | 无旧Actor旁路，无旧考试融合禁令 |
| ADD后果Native老师、严格L2 | **可复用计算事实，重新接线** | 严格Oracle与学生Q目标独立 |
| 相同冻结学生后续策略双分支CF | **必须实现** | B1/A4核心能力，不是旧Oracle同义词 |
| 学习/Checkpoint/Replay | **尽量沿用最简成熟代码，必要时重写入口** | 保持连续训练，不建立Hash准入体系 |

**模块已存在不等于能力已实现**：是否复用按新V1的输入、输出与学习语义判断，不因旧模块同名而认定实现。

## 4. Checkpoint延续政策

### 4.1 默认路径

- 训练过程持续保存Checkpoint；代码修改后优先从最近一次可用Checkpoint继续，而不是默认从头训练。
- 不使用源码Hash、commit ID、配置签名等作为加载前硬性准入条件。
- 能继承的主体网络、已经学到的F1/F2/Actor表征尽量继承；新增网络如新的Q、Reasoning可以单独初始化后参与同一个学生。
- 代码移动、文件改名、参数键名变化：由开发人员直接改载入代码或一次性转换已有文件；不维护旧API兼容层。
- 真实参数维度变化：选择性复用权重、更新必要映射；不能静默把所有参数重置为随机值然后报告“成功恢复”。
- 优化器状态可安全继续时继续；参数组发生实质变化时允许重建优化器，仍继承模型权重和训练步数记录。不把“继续利用模型参数”与“逐位复现原优化过程”混为一谈。

### 4.2 策略快照仍然必要，但不是代码版本锁

反事实价值的数学定义仍需要一个**冻结的完整策略快照π_k**。其作用是让两条分支在相同后续策略下计算回报。

- π_k指一份明确的完整学生参数和行为策略快照，不等于Git commit或源码Hash。
- 训练候选Student与用于回放的Frozen Student相互独立；正常开发训练可继续从已有模型权重演进。
- 新代码不需要与旧快照保持接口兼容；如旧快照的回放无法按新代码恢复，则开发人员决定旧CF标签是否还能用于相同教学目标、是否重新生成教师结果，不能偷偷将其改称新策略Q真值。
- 可保留一个简单的训练轮次/快照名称，供回报语义使用；**绝不据此设置阻止启动的版本门禁**。

## 5. 教材持续复用政策

- **保存有价值的数据事实**：历史行情、因果观测来源、账户轨迹、实际交易事件和有效ADD后果样本。
- **不保存格式包袱**：训练器可以使用新字段、新batch组织与新读取方式，不必让旧Reader仍然可运行。
- 新课程需要旧教材没有的Q或反事实标签时，可以在旧基础行情和账户快照上**补算新标签**；无需整体重采集、重新丢弃旧市场教材。
- 标签数学含义改变时（如旧单笔Quality分数不能直接充当长期策略条件Q），开发人员负责正确区分/转换，不作默默重解释。
- 时间顺序自主练习仍须遵守反馈成熟时间和考试数据隔离。这是**避免未来泄漏**，与教材Hash兼容无关。
- 不建立自动Corpus兼容系统、生成器Hash准入、严格Corpus认证、跨版本证书或多层文件身份校验。

## 6. 开发节奏：功能纵切、不断训练、不断继承

拒绝“所有新模块写完—所有审计完成—最后才开始训练”的流程。建议按下列可运行功能闭环逐步增加能力：

| 纵向切片 | 本次新增的真实能力 | 即时训练资产 | 本次极简完成依据 |
|---|---|---|---|
| S0 训练底座打通 | Native行情与账户 → 新Policy最小执行入口；可继承已有市场权重 | 加载旧Checkpoint及自然教材，继续市场/账户基础训练 | 可自主推进账户，可保存并恢复最新学生 |
| S1 Outcome贯通 | A3可训练后果模型接入学生完整状态 | 使用现有ADD结果教材训练Outcome，继续保存模型 | 有合法Loss更新，Outcome证据在策略前向可见 |
| S2 初始自主策略 | A5结构有初始中性Q，学生自主执行π₀ | 教师示范/有效偏好 + 学生主账户轨迹 | 唯一Actor真实WAIT/ADD；不依赖教师接管 |
| S3 策略价值 | 建立A4 Q和B1同π_k双分支CF | 先前π₀的真实和反事实经验，持续训练Q | 合法Q监督和ΔQ进入正式Actor |
| S4 思考与改进 | Reasoning辅助学习、决策改进、完整策略升级 | 继承S3的完整Checkpoint，更新下一版学生 | F2/Q/Reasoning/Actor各自有真实学习路径 |
| S5 自主闭环 | B2练习、延迟反馈、连续训练、独立考试 | 全部已有训练资产继续演进 | 学生独立跑通学习—新策略—教师free考试 |

> 编号是工程纵向切片，不是新版本的L1–L6课程。A6课程仍表示学习依赖；开发期间每完成有用能力就训练，训练可交叠进行，不人为制造阶段Gate。

**每片要有一项可运行的新功能，不以审计报告数或盈利指标算完成。** 不需要一口气训练到很高效果才能继续开发下一个核心模块。

## 7. 最小验证，不重建审计工业

仅保留关键真实性检查：

1. **金融与因果边界**：未来行情不得进入正式学生决策，Native动作合法与账户记账符合规则。
2. **完整决策链**：F2→Value/Reasoning→唯一Actor有真实调用，不存在旧F3旁路。
3. **真实教学标签**：合法ADD后果及同初态同后续策略CF有正确的账户与目标语义；截断不得伪造终局。
4. **真实学习及继承**：各能力有梯度更新；新模型可从旧模型参数继续，训练修改进入下一轮正式前向。
5. **真实独立执行**：考试没有老师未来标签，完整学生使用同一Policy。

每项优先采用最小可运行样例或少量测试，不另建专项审计框架、门禁、签名、证据包、逐阶段准入证书。异常出现时针对故障定位，不因“还可能存在其他问题”无限扩张验证。

## 8. 对A6 / B1 / B2 / C1的同步修订

### A6：学习合同不变，工程生命周期简化

- 保持L1–L6六类学习依赖、Stop-gradient规则和Q^{π_k}目标语义；它们不再等同于必须完成审计才能进入下一段训练的硬Gate。
- 每次代码小改继续现有Checkpoint训练，尽量继承已经学到的模块，允许新Head初始化；不要求源码Hash匹配。
- 保留Frozen π_k作为价值教学的语义快照，但不实现代码版本准入锁；Learner可以持续迭代和保存新参数。
- 若上游模型结构改变，开发人员负责下游适配，不建立自动模型兼容矩阵。

### B1：老师协议不变，移除兼容性形式化

- 保留Student Answer、ADD后果、同策略CF和严格Oracle来源区分，以及标签有效性/成熟时间。这些是**正确训练目标**所需的数据，而不是兼容证书。
- 不以老师生成程序的源码Hash决定标签能否继续使用。标签语义发生改变时由开发人员补算或调整。

### B2：课程保持自然教材与自主练习，允许反复迭代

- 旧教材不因代码迭代整体失效，新字段缺失可按正确含义补算；始终尽量保留旧权重和数据。
- 阶段推进不以AUC、盈利、兼容证书或成批审计作为必要门槛；工程闭环建成后继续做研究效果评估。
- 严格时间顺序实习和独立考试仍然遵守未来数据边界，不能因默认教材兼容而打破。

### C1：端到端数据流保持，移除多余版本门禁

- 仍有学生自主决策、老师后验教学、Learner更新三条链路及唯一Student Policy。
- 数据来源、反馈成熟时间、CF所用冻结策略身份仍保留最简必要信息；不能把它们误解为要做Hash管制系统。
- Checkpoint升级后，RSSM旧隐藏状态不能直接乱用；用合法历史上下文重建或按真实边界初始化即可。由开发人员保证实现正确，不增加版本认证框架。

### C3：计划方向修订（尚非Codex任务）

- 从“保护旧模块并满足旧准入”调整为“功能纵切 + 即时训练 + 参数/教材持续继承 + 关键烟测”。
- 只为真实核心依赖建立开发先后，不建多轮报告/审计阶段。

## 9. 反向Review（重点检查新原则自身的代价）

| 风险 | 反向检查 | 处理 |
|---|---|---|
| R1 无旧兼容是否推翻冻结大脑？ | 不会。冻结的是学生能力语义，不是旧API。 | 新V1唯一目标，旧流程可删除。 |
| R2 重写底座是否浪费时间？ | 有风险：一口气推倒一切会消耗大量时间。 | 只改挡路部分，能复用立即复用。 |
| R3 默认Checkpoint兼容是否会产生假恢复？ | 如果网络真的改了形状或参数名，无法无条件全量恢复。 | 开发人员优先继承有效权重，新增部分正常初始化，不隐藏随机重置。 |
| R4 教材语义更改是否污染Q？ | 旧单次交易后果不是新π_k长期Q。 | 保留历史数据，按新语义派生教学标签。 |
| R5 没有代码Hash如何保障CF可比？ | 价值定义要求同一冻结后续策略，不要求Git Hash相同。 | 使用同一个完整策略快照，最低限度记账、正确比较。 |
| R6 取消复杂审计是否可能发生泄漏？ | 存在真实风险。 | 保留少量因果、金融、反事实、梯度和考试烟测。 |
| R7 边开发边训练是否浪费早期算力？ | 网络结构变动过大时部分训练资产会失去直接参数形状兼容。 | 优先稳定主干语义，早期短程训练验证学习，能迁移就继承。 |
| R8 训练中的学生与CF冻结策略混乱？ | Q可能在Actor变动后被错用为新π的准确价值。 | 完整参数快照用于CF；新策略更新后继续评估Q，不用Hash准入。 |
| R9 旧模型/教材能否保证永远100%复用？ | 无法数学保证，尤其当网络/标签语义实质变化。 | “默认继承，必要时人工转换或部分重训”，不牺牲正确性。 |
| R10 两仓库自由重构是否产生巨大工程范围？ | 若同时大清理旧代码可能偏离核心。 | 只围绕S0–S5纵向功能切片做改动，不提前清仓重建。 |

**Review结论**：四项用户工程原则相容，前提是正确区分“无旧功能兼容”与“持续复用训练资产”，以及“反事实策略身份”与“代码Hash验证”。不要求重开A1–A5的神经网络架构决定。A6/B1/B2/C1需要的只是上述工程流程修订，避免由版本追溯演变成准入/兼容系统。

## 10. 新C2冻结建议

- V1只维护一套新学生、一条正式训练与推理主线；不保护旧S3行为。
- 两仓库自由重构，基础设施是工具而不是产品约束。
- 模型权重和教材是优先继承的资产，开发人员负责适配；不得由代码Hash作硬限制。
- 训练伴随开发推进，小步建立真实学习能力、保存Checkpoint、继续迭代。
- 验证只处理真正阻断数据真实性、参数更新和学生自主执行的问题；不另造大量审计流程。

**下一步C3**：按S0–S5制定可执行功能里程碑、最小完成条件及持续训练安排；确认后再编写Codex开发任务。
