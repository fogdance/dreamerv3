## 关键设计决定
1. **教材按“合约 × cursor”分表，不再每个行为存一份行情。**
   - 行情观测、ADD 后果、严格示范都是市场唯一事实，每个合约算一次。
   - P0–P4 行为轨迹只存账户侧数据。
   - 读取时按 cursor 拼接，标签只落在“合法且空仓”的行上。
   - 没有 manifest、Hash、签名、reconcile、coverage 报告；`source.json` 只记录来源和计数。
   - 估算：FG809 约 150 MB、几分钟（旧格式 12 GB、约 7 小时）。
2. **ADD 后果的计算方式。**
   - 用严格 Oracle 本身的真实计算 `CandidateIndex.candidate(t)`：真实 Env 开仓、索引查首个 TP/SL/全局退出、真实 `settle_exit`。
   - Quality TP 奖励按 `build_quality_suffix` 的同一公式改写。
   - 再用 `trade_facts` 补 MAE、early10、质量分。
   - 严格 L2 用 `optimize(...)` 的 `first[t]==t`；平局为“ADD 被拒、等同 WAIT”。
   - 资金下限取 `funds_certificate` 的 `required_equity_upper_bound`：权益不低于它时资金不约束，所以同一 cursor 上任何空仓账户的标签相同。
   - 去掉的旧审计：`verify_candidates`、`_verify_selected_plan`、身份 Hash、strict value cache。
3. **R4：TS 环境 `chunk_steps=0`，不再有 CHUNK_END。**
   - 不再有人工截断，也不再有重复的 reset 行。
   - 市场 RSSM 只在序列起点（真实行情起点）重置。
   - `Autonomous` 即使遇到 CHUNK_END 也不再置 `first=True`。
   - 训练随机窗口仍从零状态起步，靠 burn-in 屏蔽 loss，注释写明这不是真实断档。
4. **R3：`account_native` 由 10 维扩到 14 维。**
   - 新增四个字段：
     - `to_last_open`、`to_exit`：按交易日历计数到 `last_open`、`min(main_exit_at, liquidate)` 的市场分钟，log 缩放，事前已知、因果。
     - `funds_cover`：`clip(可用资金 / 3 手保证金, 0, 4) / 4`。
     - `margin_cover`：持仓时为 `clip(权益 / 当前保证金, 0, 4) / 4`，空仓为 1。
   - 资金充足时两个资金字段饱和。这样空仓账户只与 cursor 有关，S3 分支才能精确汇合。
5. **R2：Outcome 改为 34 类。**
   - TP、SL、OTHER_EXIT 各 11 个时间桶，再加 OPEN_AT_H（H 时仍未结束）。
   - RIGHT_CENSORED 单独按删失处理：允许删失时刻之后的全部类别。
   - 答卷字段写明期限：`p_tp_h`、`p_sl_h`、`p_other_h`、`p_open_h`，`policy.json` 记 `outcome_horizon_minutes=2760`。
   - 低优先级项：未受监督的 32 维 latent 移出 evidence；`reason_pref` 在记录中标注“S4 前未训练”。
6. **S3 反事实：分支与 π_k 自己的完整 TRAIN 正式轨迹“汇合”，回报精确，不需要尾值。**
   - 折扣：γ = 332/333 每有效市场分钟（A4，与严格老师同口径），`G(t) = r_{t+1} + γ^{advance(t,t+1)}·G(t+1)`。
   - 参考轨迹：π_k 在 FG809 TRAIN 上的正式采集，以 MAIN_ROLL 真终止结束，所以每个 cursor 的 `G_ref` 都完整。
   - 起点：参考轨迹上每个合法空仓决策点。π_k 实际执行的那个动作，回报就是 `G_ref(t)`。
   - 另一个动作的分支：恢复同一 Native 账户、同一市场 carry、同一 policy 种子计数，强制执行首个动作，之后交给同一冻结 π_k（正式 argmax）。
   - 汇合条件：同一 cursor 上，分支的 `position_state`、`action_mask`、`account_native` 与参考逐位相等，且 `min(参考未来最低权益, 参考未来最低权益 + 两者权益差)` 不低于资金下限。
     - FG809 初始资金 300000；资金下限约 5 万，`funds_cover` 约 3 万即饱和，单笔最大亏损约 1800。所以实际上的汇合点就是双方第一次同时空仓、状态相同的 cursor。
   - 汇合后：`G = 分支汇合前的奖励 + γ^{advance(t,c)}·G_ref(c)`，精确。
   - 结束分类：汇合或真终止 → `VALID_COMPLETE`；数据截断或超过上限 → `NOT_COMPARABLE`。本轮不生成 `VALID_ESTIMATED`。
   - 为什么精确：市场脑外生，种子与观测相同；π_k 确定；汇合后决策与奖励相关的账户状态一致；资金不约束。
