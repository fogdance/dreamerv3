## 设计决定
1. **`L_reason`**
   - 目标：严格 TRAIN Oracle 的比较“ADD 严格优于 WAIT”，取值等于有效且非平局行上的严格动作。数据来自 C3 §5.2 的 `STRICT_L2_DEMO`，是独立教师来源。
   - 不使用 ΔQ、ΔG_CF，也不使用 Oracle 的数值价值。
   - 损失：`sigmoid(reason_pref)` 上的 BCE，与 `L_policy_demo` 用同样的示范行、类别权重和 burn-in。
   - 梯度：`reason_pref` 只依赖 Reasoning 层，所以按前向结构，梯度只到达 `reason_in` / `reason_q` / `reason_norm` / `reason` / `reason_pref`。
   - Outcome 证据经 `SG(e)` 作为 Reasoning 的输入。`reason_pref` 仍不进入 z，不是第二个 Actor。
2. **L3 = 先验刷新阶段**
   - `loss = s_demo · L_policy_demo(教学视图) + s_reason · L_reason`。
   - 教学视图：logits 为 `[0, correction]`，去掉 anchor。β_Q=0 时与现有 L3 完全相同，所以 pi0 系列语义不变。
   - 新增 loss 系数 `reason: 1.0`。
3. **Q→Reasoning 开始学习**
   - 不新增代码路径。Q 一旦受过监督，停止梯度后的 `q_ctx` 不为 0，`reason_q`、`gate_q` 就会从这两项独立示范 Loss 得到梯度。
   - 没有任何 sign(ΔQ) 监督。上游各组照旧冻结（stop_state 加 SG）。
4. **一轮迭代（FG809）**
   - 步骤：
     1. pi1 的采集，做 CF：`cf/pi1`；
     2. L4：从 pi1 继承，学 Q^{pi1}；
     3. L3 先验刷新：示范 + 推理；
     4. 冻结 pi2：β_Q 1，κ_Q 取 `cf/pi1` 训练段 ΔG 的标准差；
     5. pi2 正式采集，并 check；
     6. 重新评估：在 pi2 上做 CF，用当前 Q 对 Q^{pi2} 目标只评估、不训练。这也是下一轮的起点。
   - 不设效果门槛，β_Q 按 C3 保持 1。
5. **`freeze` 的教学记录**：对每类报告（`train_policy`、`train_value`），取本 run 所有 checkpoint 中最新的一份。`policy.json` 里原来的 `untrained.reason_pref` 改为说明 `reason_pref` 的语义和训练来源。

- **`thinking_student/config.py`**：`loss_scales` 加 `reason: 1.0`，并更新注释。
- **`thinking_student/run.py`**
  - `LOG_KEYS['L3']` 加 `loss/reason` 和 `reason/acc_*`。
  - `POOL['L3']` 的前缀加 `reason/`，`reason/*_add` 按 `policy/n_add` 汇总，`*_wait` 按 `policy/n_wait`，`formal_add_rate` 按 `policy/n_legal`。
  - `evaluate` 在 L3 增加 `constant/reason`，即同样加权下的 log 2。
  - `freeze` 改为跨 checkpoint 收集最新报告（新函数 `reports(run)`），并替换 `untrained` 字段。
  - 不新增 CLI 命令：迭代沿用 `cf` / `train-value` / `train-policy` / `freeze` / `collect` / `check`。
- **新测试 `dreamerv3/tests/test_ts_v1_s4.py`**：复用 s2 的 `small`、`flat_states`、`update`、`group_of`、`snapshot`，以及 s3 的 `world` fixture。
  1. 只开 `L_reason`（`policy_demo` 系数为 0）：更新只改 Reasoning 参数与 `reason_pref`，不动 intuition、gate、integrator、final 及上游各组。
  2. 中性锚点：Q 不为 0 时，β_Q=0 与 β_Q=1 的 L3 loss 相同、梯度逐位一致。

     - `load_policy` 后，z = anchor + correction。

## 实跑（FG809，GPU；先用 `nvidia-smi` 看占用，GPU 上还有别的训练）
- 变量：
  - `PI1=/data/logdir/fg_single3/thinking_student/S3_PI1_FG809_20261023`
  - `S4=/data/logdir/fg_single3/thinking_student/S4_FG809_<date>`
  - `CORPUS=/data/logdir/fg_single3/thinking_student/corpus/CZCE.FG809`
- 命令写进 `$S4/s4_commands.sh`：
  1. `cf --policy $PI1/policies/pi1 --corpus $CORPUS --workers 5`，输出 `$PI1/cf/pi1`。记录完整、汇合、真终止、NOT_COMPARABLE 的计数，以及每个 worker 的重放核对。
  2. `train-value --run $S4 --init-from $PI1/policies/pi1 --cf $PI1/cf/pi1 --updates 3000 --eval-every 500`。留出集对比常数 MSE 和 `constant/sign_agree`。
  3. `train-policy --run $S4 --corpus $CORPUS --updates 2000 --eval-every 500`。示范 NLL 与 `L_reason` 对比 log 2，记录推理准确率和 `formal_add_rate`。
  4. `freeze --run $S4 --name pi2 --beta-q 1 --kappa-q auto --cf $PI1/cf/pi1 --corpus $CORPUS`。
  5. `collect --policy $S4/policies/pi2 --corpus $CORPUS --steps 30000 --chunk 1024 --mode policy`，然后 `check`。
  6. 诊断脚本 `$S4/s4_pi2_check.py`，参照 S3 的 `s3_pi1_check.py`：
     - pi2 沿 pi1 的状态，强制执行 pi1 的动作；
     - 把 z_pi2 − z_pi1 分解为 Δanchor 和 Δcorrection，统计动作翻转；
     - 受控敏感性：pi2 的 Q 置零后 correction 的变化，即 Q→Reasoning/Gate 学到的作用；
     - 记录 `reason_q` / `gate_q` 的范数。
  7. 重新评估：
     - `cf --policy $S4/policies/pi2 --corpus $CORPUS`；
     - `train-value --run ${S4}_NEXT --init-from $S4/policies/pi2 --cf $S4/cf/pi2 --updates 0`：当前 Q 在 Q^{pi2} 目标上的误差，与常数答案对比。
     - 这一步是下一轮 L4 的起点。
