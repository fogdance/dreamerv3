## 8. 发现与限制

- **单种子、单 DEV 合约。** 两条线各一个种子，DEV 只有 FG409（约 3.1 万分钟、91 个交易日）。相邻策略的 DEV 可以相差 3–4 倍（π₆ 0.00145 → π₇ 0.00051），比两条线之间的平均差还大。分档 1x 平均好于开发 run，这一点比较稳；具体哪一轮最好则不稳。
- **差别不只来自教材。** CF 代码、L4 轮次、L6 方式和采样种子都不同（第 1 节）。第 1 轮 π₀ 的差别（DEV 0.00115 对 0.00043，示范 AUC 0.80 对 0.63）只来自基础阶段，最接近“只换教材”的比较：π₀ 之前没有 CF、L4 和 L6，但两边的 L1/L2 来源也不同（这里从 F1 重训，开发 run 继承 `formal_v1`）。
- **教学题由同一版代码重建。** 开发 run 的 π₀–π₈ 和本 run 第 1–6 轮的教学题，都用分档阈值、按本 run 代码重新生成，放在 `/data/logdir/fg_single3/thinking_student/GRADED_1X_ITEMS_20261029/`，只作诊断。第 7–9 轮用本 run 自己的教学题（同一版代码）。
- **训练批次指标不是训练曲线。** “first → last”是第 100 次和最后一次更新时单个 batch 的值。
- **CF 覆盖率低：** 0.40–0.77，每轮都按探索处理。

## 9. 结论

- 分档教材的 1x 完全重训完整跑完 9 轮，每轮都通过核对。
- **比开发 run 好的：**
  - DEV reward 平均为开发 run 的 2.3 倍，8/10 个策略高于同 ADD 率的随机基线（开发 run 为 1/10）。
  - 学生更挑剔，ADD 更少，持仓时间更短；最好的 π₃、π₆ 回撤约为开发 run 的一半。
  - 对分档老师示范的 ADD/WAIT 排序更好（AUC 0.59–0.82）；Outcome 的 TP/SL 区分也多数更好。
- **没解决的：**
  - Q 仍未学到（符号一致约 0.5，Spearman 约 0）。
  - 执行的 ADD 中仍有一半左右是“差”档；在空仓后很快再进的合约上没有选择性。
  - DEV 净盈亏仍为负。
- 正确集（E-7）：在 π₇、π₈ 的新采集上没有看到 p_TP 被推高，只有第 7 轮的训练批次有苗头。10x 的复习量是 1x 的 10 倍，需要继续看这一项。
