### dreamerv3
- `corpus.py`
  - `prepare`：每个策略起一个 spawn 的 CPU 进程（每进程 1 个原生线程），同时建两份缓存：标签（L1 facts 加严格 L2 示范）和精确账户。缓存在 `/data/logdir/fg_single3/thinking_student/corpus_cache/<corpus>/`；replay 的 stepid 或标签字段变化时自动重建。
  - `account_check`：重放出的账户与同一行录制的 `position_state` 逐行核对（是否空仓、方向、持仓比例、TP 距离、持仓分钟）。
  - `CorpusWindows`：
    - 持仓行和空仓行都带精确的 `account_native`，`account_valid=1`。S1 只能精确补算空仓行，那段代码已删除。
    - `weight='demo'` 时按示范数采样 chunk。
    - `demo_weight` 是类别权重，由 `L.class_weights` 算出：balance=1 时 WAIT 和 ADD 的总权重相等，所有示范的平均权重为 1。留出集沿用训练集的权重（`demo_weights`）。
  - `label_check`：Outcome 标签和示范都只允许出现在“空仓且 ADD 合法”的状态上，否则报错。
- `labels.py`：`L2_FIELDS`、`DEMO_SPACE`、`demo_arrays`（平局或 teacher 无效的行不算示范；正式规则在平局时取 WAIT，但这不是标签）、`class_weights`。
- `brain.py`
  - DecisionBrain：Q 上下文 `[Q_WAIT, Q_ADD, ΔQ]` 先 SG，只经两个零初始化、无偏置的投影 `reason_q`、`gate_q` 进入 Reasoning 和门控。Q 未训练时这两个投影没有梯度；S3 也不训练 decision 组，所以它们一直为 0，直到 S4。
  - `beta_q` 默认 0，Q 只能通过显式锚点改变动作。
  - `formal_action(z, mask)`：正式 π 的唯一实现，ADD 合法且 z>0 才 ADD，z=0 取 WAIT。
- `student.py`
  - `policy(carry, obs, mode)`：
    - `mode='policy'` 执行正式 π。
    - `mode='explore'` 执行 μ：以 ε 的概率改为均匀选一个合法动作，否则执行正式动作。
    - 每一步都记录 π 的提议 `proposed`、`mu_prob`（即 μ(实际动作|s)）和 `explored`。答卷新增 `answer/z`。
  - `stage_groups['L3'] = ('decision',)`，`opt_l3` 只更新 decision 组（Intuition、Reasoning、Gate、Integrator、Final）。
  - `l3_loss`（`L_policy_demo`）：
    - Market、Account、Fusion 的输出都以 SG 形式进入。
    - 只有满足以下全部条件的行计入损失：处在合法空仓 ADD 状态、在市场重置后的 burn-in（16 步）之后、有示范。每行的权重就是数据里的类别权重。
    - 指标：`p_add_on_add/wait`、`acc_add/wait`、`add_rate`、`n_demo/add/wait/legal`。
- `config.py`：`decision.beta_q=0`、`demo_burnin=16`（small 预设为 2）、`explore_eps=0.05`、`loss_scales.policy_demo=1`。
- `run.py`
  - `train-policy`：L3 训练，训练前、中、后在留出集上评估。参考值是常数答案：均匀的 WAIT/ADD 在完全相同的行上的类别加权 NLL，即 ln2·Σw/n。
  - `freeze`：写 `policies/<name>/agent.pkl` 和 `policy.json`。`policy.json` 记录以下内容，都只作记录，不作加载门禁：
    - 动作选择方式和规则、μ 的设置、RSSM 初始化方式；
    - 推理设备与计算精度：bf16 和 f32 在 z≈0 附近可能翻转动作，所以 CF 和考试要用相同的设备和精度；
    - 全部 `ts` 系数（包括 β_Q）、教学设置和最终评估；
    - Reward 版本、teacher 来源、两仓 SHA 和 dirty 状态、参数 sha256。
  - `load_policy`：按快照重建学生并加载参数，默认用快照记录的推理设备。
  - `collect`：自主 Native 采集。
    - 每块写 `steps/<n>.jsonl`（答卷、提议、执行、μ、探索标记、账户经历）和 `replay/<n>.npz`（决策时的数组），然后原子写 `state.pkl`。`state.pkl` 包含 Native 账户、市场记忆、待决 observation 和 policy 种子计数。
    - 中断后从最后一个完整块续采。
    - CHUNK_END 后市场记忆重置、账户延续，与 corpus 的做法相同。
  - `check`：核对一次采集。检查正式规则、Mask 和 TP/SL 点数；给出 TRAIN corpus 时，再把每次 ADD 与 teacher 的独立事实对照。
  - CLI 的默认设备改为 cuda；`collect` 默认用快照记录的设备。
- 测试：新增 `tests/test_ts_v1_s2.py`，共 7 项；S0 和 S1 的测试随新的 policy 模式一起更新。

### 最小验证（C3 S2）
- **一段短自主回放 + Actor 梯度更新**：上面的 μ 采集（3000 步）和 3000 次 L3 更新（单次更新的参数组边界见测试）。
- **正式决策与 CF/考试同一规则**：
  - 正式规则只有一处实现 `brain.formal_action`，`student.policy(mode='policy')` 调用它。S3 的 CF 续行和 S5 的考试都通过 `run.load_policy` 加载同一快照，并调用同一个 `student.policy`。
  - 三份采集共 34263 行：每一行的提议都等于 `int(ADD 合法 且 z>0)`，违规 0。正式模式的每一行都执行了自己的提议，且 μ=1，违规 0。
  - π0 在合法空仓状态上的 z 介于 −4.70 和 3.72 之间，中位数 −1.89。z>0 恰好 50 次，对应 50 次 ADD。
- **中断续采逐位一致（真实 TRAIN、GPU）**：`pi0_explore`（1500 步后在新进程中续采）与 `pi0_explore_full`（一次跑完）相比：
  - 6 个 jsonl 文件逐字节相同，174 个 npz 数组逐位相同，`meta.json` 只有 `resumed` 不同（1 和 0）。
  - 步号连续；CHUNK_END 后市场记忆重置 2 次，账户延续。
  - GPU 开启了 `--xla_gpu_deterministic_ops`。这同时说明：从同一快照新建的进程，在同样的状态上会做出同样的决策。
- **Mask**：执行的 ADD 全部发生在 ADD 合法的状态上，被屏蔽的 ADD 为 0。代码在执行前也会检查，违规就报错。
- **TP/SL**：
  - Native 账本里每一笔 TP 至少 +5 点，每一笔 SL 至少 −30 点，违规 0。
  - 把 π0 的每次 ADD 与 teacher 的独立事实逐笔对照：teacher 事实取自始终空仓的 P0 在同一决策分钟的 L1“现在 ADD 后持有”。时间戳和空仓状态先核对，再比较出场类型和出场分钟；持仓中的交易要求 teacher 的出场分钟在采集结束之后。
    - `pi0_policy`：50/50 一致，含 1 笔 MAIN_ROLL 对应 teacher 的 OTHER_EXIT。拒单 0，无法核对 0。
    - 两份 μ 采集各 3/3 一致。
  - π0 这 50 笔的 Native reward 合计（−18.9623）与 teacher 对同样入场给出的 `configured_reward` 之和逐位相等。
- **ADD 比例**（只记录，不设门槛）：正式 π0 在合法空仓决策上为 11.8%（50/423）。留出集示范状态上为 22.8%，见训练表。

### π0 的行为（诊断，不是验收项）
- π0 没有优势，与随机入场相当：
  - π0 的 50 笔中 TP 占 70%，平均 −0.379/笔。
  - P0 全部空仓状态随机入场的基准（teacher 事实，n=28240）：TP 72.5%，SL 25.6%，平均 −0.361/笔。
- 在 π0 自己轨迹的 423 个合法决策点上：
  - 严格 L2 示范为 ADD 的状态只有 2 个，π0 都选了 WAIT。
  - π0 的 50 次 ADD 中，49 次落在 L2 为 WAIT 的状态，另 1 次落在无示范的状态。
- 解释：
  - 440 个 ADD 示范只够形成一个很弱的行为先验。
  - 类别平衡让 π0 在示范上的 ADD 比例远高于自然比例（0.94%），但并没有强制。
  - 改进要按 A6 的路径走：π0 的 Native 经验和同策略 CF → `Q^{π0}` → ΔQ 锚点（S3）。
