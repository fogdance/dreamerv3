## 入口

| 入口 | 作用 |
| --- | --- |
| `python -m dreamerv3.thinking_student.feedback --collection C --corpus K [--cf CF] [--kappa-cf CF …] [--kappa-floor F] --out O` | B1 教学题：π_k 在一个合约上的全部决策行，写 `items.npz` 和 `summary.json`；`--order` 只接受 `OFFLINE_TRAIN` |
| `run train-outcome … --feedback O … --remedial-fraction F` | L2 复习：每批 round(F·B) 个窗口覆盖后果错行，其余窗口自然抽样，标签相同 |
| `run train-value … --feedback O … --remedial-boost B` | L4：决策错的 CF 行在起点权重里 ×B |
| `run train-policy … --feedback O … --remedial-fraction F` | L5：示范错补课窗口；示范错 = 决策错 ∩ strict 有效 ∩ teachers_agree |
| `run freeze … --feedback O …` | lineage 记教学题目录、`teaching_order`、`time_ordered` |
| `formal_train iterate`，配置块 `iteration.l6` | 从 `from_round` 起，每轮 collect → check → CF → feedback → L2 复习 → L4 → L5 → freeze → exam |

## 结论

1. **闭环跑通。** OFFLINE_TRAIN 的 L6 在 18 个 TRAIN 合约的开发 run 上实跑了三轮，满足 C3 S5 的最小闭环验证：
   - 学生自己采集；
   - 动作合法、与事实一致；
   - 教学题带来源、ready_at 和有效性；
   - 补课进入 L2、L4、L5；
   - 冻结新策略，并做 Teacher-free 的 DEV 考试；
   - CF 覆盖不足的一轮按规则保留价值脑。
2. **成绩。** 开发预算下没有看出 L6 改善了 DEV 成绩，`best_dev` 仍是 `pi_0001`。
3. **固定比例补课的副作用：**
   - 后果错补课让后果脑在自然分布上校准变差。
   - 错题很少时，同几道题会被反复补课：第 8 轮每道约 133 次。10x 的 L2 复习是 2,000 次，重复次数也会乘 10。
   - L5 的示范错补课削弱了约三分之一的自然改进。
   - 改法需要用户决定，记在 `TODO.md` 的 E-7。
