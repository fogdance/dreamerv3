## M — 教材重建

### M1 新教材格式（gym `research/ts_v1_corpus.py`）

**分表方式**：教材按“合约 × cursor”分表。下面三类只取决于市场，每个合约只算一次。

| 表 | 内容 | 标签来源 |
|---|---|---|
| `market/` | 因果 E 观测 | — |
| `facts/` | 空仓 ADD 的原生交易后果 | `TEACHER_ADD_FACT` |
| `strict/` | 严格 TRAIN Oracle 的 WAIT / ADD | `TRAIN_STRICT_ORACLE` |

`behaviors/<P>/` 只存 P0–P4 行为账户的账户侧数据。

**`source.json`**：只记录 TRAIN 池行、输入、各标签的来源与 `ready_at`、计数和耗时。没有 manifest、Hash、签名或 reconcile。

**ADD 后果的计算**：
- 用严格 Oracle 的 `CandidateIndex.candidate(t)`：真实 Env 开仓，再查首个 TP / SL / 全局退出，再做 `settle_exit`。
- Quality TP 奖励用 `quality_tp_reward` 改写。
- `trade_facts` 补上 MAE、early10 和质量分。
- 生产时随机抽 32 个 cursor 做原生逐分钟核对，结果不一致就报错。这是唯一保留的交叉检查（C3 5.9）。

**严格示范 = 精确 DP 的 `first[t] == t`**：
- 平局：一个 ADD 的价值与 WAIT 完全相等。平局行不当示范。平局有三种：
  - ADD 被拒；
  - 优化器判为精确相等后取了 WAIT（`optimize` 新增的 `suffix['tied']` 列表）；
  - 零反馈交易，并且从 t+1 起的最优计划在它释放之前不开新仓。
- 亏损的交易，或会挡住更好交易的交易，算严格 WAIT。

**对齐 C3 §5**：
- 标签只取 P0 账户（`LABEL_ACCOUNT='P0'`，EDU-R10）。
- 资金下限取 `funds_certificate` 的 `required_equity_upper_bound`（FG809 为 19200）：权益不低于它时资金不约束，同一 cursor 上任何空仓账户的标签相同。

**测试**：gym `test_ts_v1_corpus.py` 8 项通过。
- facts 与原生逐分钟结果一致；
- P4 执行的就是严格计划；
- 没有重复 cursor；
- 精确 DP 的 ADD / WAIT / 平局判定正确；
- 教材目录搬走后仍可读取。
