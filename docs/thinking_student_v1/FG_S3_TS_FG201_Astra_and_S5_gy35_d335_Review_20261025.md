### 特别重要：单改 `couples()` 不够

`value.py:207–230` **在启动worker之前**调用 `Reference.decidable(t,max_steps)`，将“不可能按**旧耦合门槛**闭合又不能到终止”的分支放入预算集合；未抽中者直接记 `UNAVAILABLE_BUDGET`。

因此若只增加“未来相关状态完全一致时可以精确耦合”，旧 `Reference.decidable()` 仍以全局 `couple_from` 预判：FG201原本1,298条预算未模拟分支**连新耦合检查的机会都没有**。

**这是研究方案实施时必须同时修的正确性/覆盖缺口**：更新预算预筛选语义，让“尚不能证明不需模拟”与“已证明无法闭合”明确区分。可先给所有合法fork提供一个小的、相同的精确合并探测预算，再对确实未闭合的分支按既有预算/尾界接续；不能为了提速把未模拟者当不可完成。保留原`cf_max_steps`的含义，不产生虚构标签。

### 算法最小实施顺序

1. 加 `strict_future_state_equal` 精确共享通道；既要包含当期账本、reward活动状态、pending、规则状态和必要的随机/序号状态，也要处理日志等与未来无关的历史字段；以FG201 t=7 四步后缀为回归样本。
2. **同时修改 `Reference.decidable`／`run_cf` 的 budget prefilter**，避免可短期精确重合的fork在启动模拟前已被扔掉。
3. 共享单合约外生MarketCarry推理、减少重复参考重放与完整历史快照复制，保留账户依赖和seed对齐；先小样Native逐步对照。
4. 精确共享仍不能闭合时，再实现带明确上下界的`VALID_ESTIMATED`，保存折扣前缀/MarketClock有效分钟/误差界；整条 Reader、Q损失、S5错误标记都必须认识区间。不得仅把status改名或把CAP当TERMINAL。
5. 事件驱动和带账户状态的按需DP留在后续性能阶段；不得无条件压缩为单个 `V(t)`。

## 4. 需处理的问题（按最小优先级）

### P0 — CF精确共享修复必须连带改预算筛选

见§2。否则优化可能只对少数被抽中的250个分支生效，原有1298个 `UNAVAILABLE_BUDGET` 仍无标签。应有“FG201早期fork在短暂同状态后精确闭合且被实际调度”的测试，不仅是单独调用 `Reference.couples` 的单元测试。

### P1 — CF重算后，S5教学题可能复用旧版本（影响后续FG201修复）

`feedback.py:368–370` 仅凭 `summary.json` 存在就跳过；`formal_train.py:330–348` 也按summary判断已完成。因此后续改进CF算法、同名目录中重生 `pairs.jsonl` 后，**已有反馈仍保留旧 `cf_valid/delta_g/decision_error`**。这些反馈是旧教材产物，不会自动补充新的有效成对标签。

处理方式：修复CF后，对**受影响策略＋合约**显式重新生成对应 feedback（并视是否已有 learner 训练，决定新 run/新轮次），不要为此加入逐batch文件Hash或全量认证。CF自身 `meta.json` 也不能在旧产物存在时直接视作“新算法已验证”；重新生成时保持政策版本关联。

### P1 — S5闭环还需一次真实执行验收

按现有配置完成第7–9轮（或先挑一轮作小范围验收）：核对 `feedback → L2 → L4(或合法跳过) → L5 → freeze → DEV`，含真实补课曝光、策略冻结和中断恢复。记录`S5_RECORD`、DEV基线与ckpt，不需要重复旧S3审计。此事与FG201 CF改造分开验收，避免在旧CF缺覆盖的条件下误判S5失败。

### P2 — 后果错暂只覆盖事件类型，不覆盖完整Outcome预测误差

`feedback.fact_items`保存了`fact_kind/held/exit/ready_at`和事件整体概率`p_realized`，**没有对早期逆行、MAE、Quality或TP时间分布单独定义错因/补课标签**。虽然L2正常损失仍训练这些头，但S5“错题补课”目前主要依赖事件总体概率<0.1。若未来发现快速TP5学习不充分，优先增加Quality/TP时间/Risk误差选题，不必重新设计大脑。此项不阻止最小S5验收。

### P2 — 恰好在Outcome H发生删失的边界漏标

本地用纯Python成功复现：`H=2760`，`RIGHT_CENSORED`且`held_minutes==H`时，`labels.allowed_classes()`已证明只能是`OPEN_AT_H`，但`feedback.fact_items()`因使用`held>H`而输出`realized=-1`，将此已知结果弃权。建议该情形按完整存活H处理，补一条小测试。对一般训练影响预计很小。

### 后续接口 — 估计CF不能直接喂给S5

`feedback.pair_items:278–291` 只以`delta_g is not None`判断有效与算 regret，当前producer仅给`VALID_COMPLETE`数值，尚安全；引入`VALID_ESTIMATED`后必须显式检查误差界，用regret下界决定“肯定错题”，偏好区间跨零则弃权，Q Reader与 κ 统计也必须配套更新。
